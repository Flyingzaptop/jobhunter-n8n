# Local LM Studio provider

Set `OLLAMA_PROVIDER=lmstudio`, `LM_STUDIO_BASE_URL=http://127.0.0.1:1234/v1`, and both `LLM_FAST_MODEL` and `LLM_STRONG_MODEL` to the exact ID returned by `/v1/models`. The gateway accepts loopback endpoints only and never switches models or providers. `LMSTUDIO_BASE_URL` is accepted as an alias.

Load the model with a 32768-token context in LM Studio and leave it loaded. Set `LM_STUDIO_CONTEXT_LENGTH=32768` to match that loaded runtime (`LMSTUDIO_CONTEXT_LIMIT` is an alias). The gateway does not unload the model, probe Ollama, or attempt to increase its runtime context. It conservatively checks the complete input UTF-8 byte count plus output allowance and framing reserve against the configured loaded context, and fails without truncating facts if it cannot establish room.

If the byte bound exceeds that limit, the installed `@lmstudio/sdk` resolves only the exact already loaded instance from `listLoaded()`, applies its native chat template to the complete messages, counts tokens and reads the actual context length. The complete native count plus output allowance and 2048-token reserve must fit both actual and configured limits. No SDK `model()` or `load()` call is made. The native approach follows [LM Studio's tokenization documentation](https://lmstudio.ai/docs/typescript/tokenization); actual measured input tokens are recorded in request stats.

Production inference uses the SDK handle for the exact already loaded instance and overrides `enableThinking:false` for each request. It sets `temperature:0`, `maxTokens` to the output budget, `contextOverflowPolicy:'stopAtLimit'` and an abort timeout. This does not change the model's global template or settings. Current native token measurement uses the model's base template, with the 2048-token reserve covering the small formatting difference when thinking is disabled.

Set `LLM_TIMEOUT_MS=3600000` for local runs that may take up to one hour. The LM Studio provider accepts 1000–3600000 milliseconds, retains the configured deadline when cloned for fit/CV models and keeps the model resident across requests. Other providers remain capped at 600000 milliseconds. A long timeout permits slow generation without changing output/context budgets or validation. Fit and CV workers must continue to share their existing model mutex so concurrent application batches do not compete for this loaded instance.

`LMSTUDIO_STRUCTURED_FORMAT=json_schema` (default) sends SDK `structured:{type:'json',jsonSchema:schema}`. If the selected runtime does not support this, explicitly configure `LMSTUDIO_STRUCTURED_FORMAT=strict_json`; this uses schema instructions with the same Ajv and application semantic validation. No automatic mode or provider fallback occurs. Both modes allow at most one complete repair attempt and reject incomplete output or an unexpected returned model ID. `/v1/models` remains the read-only health endpoint. An injected fetch implementation retains the OpenAI-compatible transport test seam; production uses the SDK.

The model is kept resident by LM Studio's runtime configuration. Requests do not include unload instructions or modify idle TTL. Verify the loaded model and TTL with LM Studio before a production run. Stats identify `provider=lmstudio` and the local model, without remote-model provenance.

SDK request stats expose lifecycle stage, prompt processing progress and token counters, time to first token, fragment count and elapsed time; callbacks never record model fragments or reasoning. An inference timeout returns fixed `INFERENCE_TIMEOUT` after one attempt without immediately retrying. An independent hard deadline ends the client wait even if the SDK does not settle its promise after abort; an explicit prediction-handle `cancel()` is sent on abort while preserving the loaded model. Cancellation is best effort and should be checked against the server lifecycle if the runtime becomes unresponsive. The installed SDK exposes cancellation for a prediction handle, not a public cancel-all-predictions operation.
