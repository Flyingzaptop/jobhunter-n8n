# Continuous controlled pipeline

Start only with explicit local authorization: `CONTINUOUS_WORKER_ENABLED=true`, `DRY_RUN=true`, `ALLOW_REAL_SUBMIT=false`, then run `node --env-file=.env scripts/continuous-worker.mjs` from the repository root. The process migrates the database and uses a 32-connection pool for independent lane locks and operations. Keep the LM Studio instance loaded and configure `LLM_TIMEOUT_MS=3600000` for slow local requests.

Six independent session-locked lanes handle ingestion, cheap screening every 60 seconds, sequential alternating fit/CV work, two application preparation workers, and notifications. Screening does not wait for a complete source scan. Six source collectors run concurrently, serializing requests to the same host. Completed source cycles wait one hour; truncated scans retain published pagination cursors for continuation. Fit processes one actual job per turn. Fit, CV and grounded employer prose retain the existing shared advisory model mutex. An application waiting for manual input or review does not pause other applications, ingestion or model work. Global runtime pause remains respected.

Employer prose uses durable job/profile/policy/form bindings and a separate verifier. Infrastructure failures retain their safe error codes, wait five minutes and do not consume semantic attempts. Holding the exclusive model lock permits recovery of orphaned GENERATING rows after a worker restart. Optional blank additional notes do not delay navigation.

Every lane tick reloads the local profile and search policy into a private snapshot. A pending fit operation keeps its original snapshot; subsequent ticks see changes. Eligibility requires current profile, source and policy hashes, explicit current location-policy compatibility and no configured vacancy/company/country exclusion. Preparation does not require a confirmed hiring route for a location-compatible REVIEW candidate. A policy/profile change during CV generation prevents registration until current analysis is available. Configuration is checked again before preparation and application execution.

CV selection requires the latest non-rejected analysis with score at least 45, complete requirements, no hard blockers, current profile hash and current OPEN source content. Durable CV claims include canonical analysis, source content and profile hashes. Existing matching CV artifacts also prevent duplicate generation. Set `CV_AUTOMATED_RENDER_QA_ENABLED=true` and `POPPLER_BIN_DIR` to enable independent automatic PDF layout QA and registration after the existing factual/identity/PDF checks. Passing work becomes `COMPLETED`; unavailable or failing independent QA remains `DRAFT_PENDING_VISUAL`. The proof explicitly identifies an automated reviewer. The manual visual review tool remains available. Preparation consumes only approved, application-eligible CV versions; existing evidence checks and current posting verification remain mandatory.

CV keys include the current factory template version. An old template or missing/failed target tailoring QA cannot suppress regeneration or enter preparation. Notification delivery independently drains CAPTCHA handoffs and queues/sends newly registered CV documents using a shared worker-start cutoff. Existing durable document delivery handles configuration waits and deduplication; a failure in one notification type does not prevent the other from being attempted.

Migration 010 stores claims, leases and safe outcome codes. A one-minute heartbeat extends active work leases; interrupted RUNNING claims can be recovered only after the lease expires. Completed work and user-waiting outcomes are deduplicated. Failures retry after five minutes. Lane status stores no prompts, CV text, contact details or model output. Inspect `continuous_worker_status` and `continuous_work` for state. Telegram credentials can be configured later; waiting delivery does not stop other lanes. Keep the existing Telegram update poller running for replies.

All preparation is a controlled dry run with real submit disabled. Stopping the worker does not unload LM Studio. Graceful shutdown waits for the current operation; model requests retain their configured hard deadline.
