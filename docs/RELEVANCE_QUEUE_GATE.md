# Production gate relevance queue and actual fit batches

The cheap queue screens **13,911 actual canonical vacancies**. Initial deterministic
screen: **586 QUEUED**, 13,320 LOW_PRIORITY, 5 CLOSED. The top 500 rows are exported
with titles, source links, geography, score and each weighted signal. This costs no
Ollama calls and creates no fit analyses. It is an ordering heuristic, not a
candidate match/decision, employment eligibility conclusion or acceptance claim.

Signals prefer mechanical/R&D/CAD, simulation/test, robotics/automation, Python/
data and IT support titles. Junior, student and internship vocabulary receives a
bonus, including German/French/Polish variants. Incidental body keywords cannot
qualify an accounting/sales title. Senior titles are deprioritized. Every score
component records its matching original field and reason; version and content
hash make revisions auditable. Low priority records are retained, not deleted.

Wrocław/Poland and known European locations receive priority hints. Remote,
EMEA, worldwide and city-only evidence never silently establishes work permission
from Poland. European onsite/hybrid remains relocation review. Unknown location
and salary remain unknown; compensation is not a fabricated score component.

Migration 006 stores queue status, rule version, input hash, reasons, location
class, seniority, hydration need, retry attempts, receipt hash and claimed run.
`fit_batch_receipts` links the exact job/profile/policy/model/prompt hash to the
actual persisted analysis. A repeated batch skips unchanged completed hashes.
Changing candidate facts, source text, policy, model or prompt permits reassessment.

## Real sequential model processing

`runRelevanceFitBatch` requires explicit exclusive local GPU authorization.
The production script also requires dry run with real submit disabled. A database
advisory lock prevents concurrent queue batch runners. It cannot by itself stop
another unrelated Ollama script: root coordinates GPU ownership.

Before each analysis, the runner performs fresh official OPEN verification and
hydrates summary-only official SmartRecruiters details. Unknown, blocked and
closed records never gain artificial OPEN/fit readiness. Real Qwen supplies only
structured source/fact mapping; existing validation, education/professional
years/language gates and deterministic scoring/routing stay authoritative.

The batch is bounded by unique model-attempted jobs and elapsed time, respects pause,
and emits real PostgreSQL stage-3 operation/job events. Completed analysis and
receipt are committed together. A process restart recovers unfinished fit jobs;
this may repeat inference after a crash, but never silently duplicate a completed
hash receipt. Transient transport errors back off; semantic/configuration errors
dead-letter. A changed hashed input permits retry of an old dead-letter record.
No browser application or real submission is started by this runner.

```powershell
# No GPU calls: persist/rebuild queue and export 500 candidates
node --env-file=.env scripts/relevance-queue.mjs

# Only after root grants exclusive GPU use for this run
$env:JOBHUNTER_FIT_BATCH_AUTHORIZED='true'
node --env-file=.env scripts/relevance-queue.mjs --analyze --max-jobs=200 --max-minutes=480

# Read-only current operation, receipt counts and actual NONREJECT results
node --env-file=.env scripts/relevance-queue.mjs --status
```

The first authorized actual run is `04058fac-6d01-4049-b120-8cb06eea5d42`.
Its progress is persisted in `operation_runs`/events and queue states; the final
report is written as `tests/results/fit-batch-<operation_run_id>.json`. Until it
finishes, no 200-job completion claim is made. `--max-jobs` bounds actual model
attempts; UNKNOWN/closed skips do not consume that model budget. They are reported
separately from actual completed analyzed counts. A time budget or semantic
failure can still prevent 200 validated outputs and must be reported honestly.

## Curated reference calibration

Twenty actual employer source clauses were separately inspected against verified
candidate YAML by the assistant. Labels explicitly carry
`review_method: ASSISTANT_MANUAL_REVIEW`, `author_type: ASSISTANT_AGENT`; they are
not generated by Qwen and are not falsely attributed to the human user. Five
held-out cases are marked separately from fifteen development references.

Cases include positive CAD/Python/statistics/project evidence, unfinished-degree
negative cases, German language/onsite uncertainties, related ongoing study,
insufficient duration evidence and supported versus inflated skill levels.
Exact source text and provenance fact IDs are retained. A missing candidate fact
is UNKNOWN rather than an invented ability or automatic known incapability.
Assistant reference labels themselves may need independent adjudication; they
are not a universal human gold standard and do not override runtime fit outputs.

`scripts/fit-calibration-reference.mjs` validates every quote against the current
actual PostgreSQL vacancy before storing it. It exports references and exact-quote
comparisons against the latest saved model analysis. Missing source mapping is
reported explicitly; disagreements are review findings, not silently fixed fits.
The root can review these without imposing an unnecessary human approval gate.
No USER_REVIEWED status is written by the assistant.
